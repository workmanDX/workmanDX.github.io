Plant Journal

Android-first app for houseplants and bonsai: collection, care schedules, a photo journal with AI analysis, and per-plant streaming chat.

Personal prototype I use day to day. Not on the Play Store. I built it to learn a full mobile + backend stack outside Salesforce: auth, row-level security, file storage, release variants, and AI behind a server boundary.

Stack

  • Expo SDK 56, React Native, TypeScript, Expo Router
  • expo-dev-client (custom native builds, not Expo Go)
  • Supabase: Auth, Postgres + RLS, Storage, Edge Functions
  • Gemini for photo analysis and plant chat (server-side only)
  • EAS build variants: development, preview, production

Architecture

App (Expo)
  → Auth (PKCE, session in SecureStore)
  → Postgres + RLS
  → Private Storage (plant and chat photos)
  → Edge Functions (verify JWT + plant ownership)
       → Gemini (analyze photo, stream chat)

The mobile app holds only the Supabase URL and anon key. Gemini credentials stay in Edge Function secrets. Chat threads live in Postgres, not a third-party chat SaaS. Photo uploads are downscaled to 1024px on the long edge before Storage.

Decisions worth looking at

  • Security boundary. RLS on every table, storage paths prefixed by user id, Edge Functions re-check plant ownership before calling Gemini. Same idea as Salesforce sharing: the client is not the authority.
  • AI as a product feature. Analysis and chat receive a plant context pack (species, care history, garden timezone / hardiness). Chat is scoped to one plant, streams NDJSON from the plant-chat function, and persists the assistant message when the stream ends. Usage is logged per user.
  • Release variants. Three package IDs install side-by-side: Dev talks to Metro, Preview is a standalone APK I use as a daily driver, Production is the store-shaped bundle. JS-only changes reload in Dev; native modules and app config require an EAS rebuild.

Status

Core loops are in place: plants, care, photos + analysis, per-plant streaming chat, account deletion. I run Preview on a phone and Dev in parallel for ongoing work.

Still open: monthly AI spend caps, broader automated tests, query pagination for large collections. I would not put strangers on this build until quota is enforced.
